## Why

助手目前只有"一问一答 + 工具调用"的最小形态:能记账(`add_transaction`),但模型决定直接写入,用户看不到要写什么就要承担记错的风险;能查单月数据,但"和上月比怎么样、这个月钱花哪儿了"这类复盘要用户自己组织问题;应用积累的标签、搜索等数据能力(见 add-search-tags 变更)助手完全用不上。同时导航是 8 个平铺入口,总览页信息密度低,助手的入口弱,与"记账 + 资产管理 + 本地大模型助手"的定位不匹配。

## What Changes

- **记账确认流(Ask-first)**:助手识别到记账意图后,不再直接调用 `add_transaction`,而是先返回一张"待确认账目卡片"(金额、收/支、分类、日期、账户、备注),用户点"确认入账"才写入;缺分类/金额等关键字段时模型先追问。支持"把刚才那笔改成 35 元"式的追改(确认前可改,确认后提示去账目页编辑)。
- **一键复盘**:助手新增"生成本月复盘/年度复盘"能力。数据由 Rust 汇总(总收支、TOP 分类、环比、预算达成、订阅合计、目标进度),模型只负责解读和写成可读的报告;复盘可一键保存到报表页(新表 `saved_report`)。
- **助手联网检索数据面扩展**:新增只读工具 `find_transactions`(按关键词、分类、金额区间、日期区间查账目)与 `get_month_compare`(本月 vs 上月收支对比),对齐 add-search-tags 变更的数据模型。
- **账单导入助手**:粘贴微信/支付宝导出的账单文本,助手逐行解析、映射分类,输出"导入预览表",用户勾选确认后批量入账;金额以分为单位校验,重复行(同日期+同金额+同摘要)标灰默认不导入。
- **总览页重构 + 导航分组**:侧栏由 8 项平铺改为 3 组(记账:总览/账目/预算;规划:目标/订阅;分析:报表/理财);总览页顶部为净资产卡,新增"本周洞察"卡(纯 Rust 规则计算,不调模型:预算消耗速度、大额支出、订阅临近扣费),卡片上的"问助手"按钮把对应问题带上下文送入助手。
- **助手改为全局抽屉**:聊天从"侧栏底部小窗"改为右侧滑出抽屉,任何页面 ⌘K(或点右下角悬浮球)呼出,当前页面的上下文(如报表页 = 当前月份)自动带入对话。

## Capabilities

### New Capabilities
- `agent-confirm-write`: 助手写入类操作的确认流(卡片字段、追问规则、追改规则、确认/取消行为)。
- `agent-review-report`: 复盘的数据口径、生成流程、保存与展示。
- `agent-import-assistant`: 账单文本解析、分类映射、预览确认与批量入账。
- `overview-insights`: 总览页洞察卡的规则、触发条件与"问助手"联动。
- `agent-drawer`: 全局抽屉的唤起方式、上下文带入与快捷键。

### Modified Capabilities
- 导航结构(NAV 数组加 `group` 字段,现有 8 页不合并不删减,仅分组)。
- 助手工具清单:`add_transaction` 改为产出待确认卡片而非直接写入;新增 `find_transactions`、`get_month_compare`、`save_report`。

## Impact

- Rust:`agent.rs` 工具协议新增 `pending_write` 类型(确认卡片由前端渲染);新增 `insight.rs`(纯规则洞察,附单测);`report.rs` 增加保存/列出复盘;`import.rs` 负责微信/支付宝两种格式的文本解析(GBK/Excel 导出先由用户粘贴文本,不读文件,避免引入编码依赖)。
- 数据库:新增 `saved_report`(报表)与 `tag`(若 add-search-tags 未先行)表,仍走 `CREATE TABLE IF NOT EXISTS` 迁移;备份 `TABLES` 同步补充。
- 前端:`agent-panel.tsx`(抽屉 + 确认卡片渲染)、`overview.tsx` 重构(净资产卡 + 洞察卡)、`App.tsx` NAV 加 group 与悬浮球/快捷键;报表页加"已保存复盘"列表。
- 安全与隐私:所有模型请求仍只带当前对话所需工具结果;导入文本中的对方昵称等敏感列不落库,仅保留金额/日期/摘要。
- 免责:复盘与洞察均为数据陈述,不给出投资建议,沿用现有"不构成投资建议"规则。
