# design:enhance-agent

## 一、设计原则

1. **Ask-first / Never-do 分层**:助手读数据 Always do;写数据(入账、改预算、改估值)Ask first——先出卡片、人确认、后执行;删除、批量覆盖 Never do(助手不做,只指路到对应页面)。
2. **计算归程序,表达归模型**:所有数字(环比、占比、消耗速度)由 Rust 算好给模型,模型只解读,杜绝模型口算错数。
3. **不新增用户必须学习的东西**:入口都是"已有页面上的一块卡/一个按钮",不引入独立新页面。

## 二、功能设计

### 2.1 记账确认流(`agent-confirm-write`)

**流程**:用户说"午饭花了 35" → 模型调用 `add_transaction` → 后端不直接落库,返回 `pending_write` 事件(含建议分类) → 前端在对话流里渲染确认卡片 → 用户点"确认入账" → 前端调既有 `create_transaction` 命令落库 → 卡片变为"已入账 ✓"态。

**确认卡片字段**:收支、金额、分类(可下拉改)、日期(默认今天)、账户(可空)、备注(可改)。所有字段前端可改后再确认,不必回对话里重新说。

**追问规则**(模型侧,写进 system prompt):金额缺失 → 问金额;收支方向不明确(如"转账") → 问是支出还是收入;其余字段(分类/账户/备注)允许留空,确认卡片上自行补。

**追改规则**:确认前 → 直接改卡片字段;确认后 → 卡片固定,提示"已入账,可在账目页修改";同一条消息里说"改成 40"→ 模型重新出一张卡片替换旧的(旧卡片置灰)。

**验收(GWT 摘要)**:
- Given 助手识别出记账意图,When 用户提供金额与用途,Then 先渲染待确认卡片且数据库无新记录;
- Given 待确认卡片,When 用户修改分类后点确认,Then 落库的是修改后的值;
- Given 卡片未确认,When 用户关抽屉再打开,Then 卡片仍保留(会话内持久)。

### 2.2 一键复盘(`agent-review-report`)

**数据口径**(Rust `review_summary(month)` 一次算齐):
- 总收入/总支出/结余,环比上月(%;
- TOP5 支出分类及占比;
- 预算:总额、已用、剩余天数、日均可用 = 剩余 ÷ 剩余天数(不足 1 天按 1 天);
- 订阅:本月固定支出合计、明年到期续费的年付项;
- 目标:每个目标的进度与近三月实际速率 vs 要求速率;
- 大额:单笔 ≥ 月均单笔 5 倍的支出(口径注明"估算阈值")。

**生成流程**:入口两处——报表页"生成复盘"按钮、对话里说"复盘一下这个月"。模型拿到 `review_summary` 结果后输出 Markdown 复盘(固定小节:概览/花哪儿了/预算/固定支出/目标/一句话建议),建议部分不得出现具体投资品种。

**保存**:对话里的复盘带"保存到报表"按钮 → `save_report` 落 `saved_report`(月份、生成时间、Markdown 正文);报表页新增"已保存复盘"列表,可查看/删除。

**验收**:复盘内每个数字与 `review_summary` 返回一致(测试:喂固定数据,断言模型输出中的数字出现);未生成模型的月份(无账目)给"本月暂无数据"而不是空报告。

### 2.3 检索工具扩展

- `find_transactions`:参数 keyword / category / kind / min_amount / max_amount / from / to / limit。SQL 层 LIKE + 区间,返回 ≤50 条,摘要含日期、金额、分类、备注。
- `get_month_compare`:返回本月与上月各自的收入、支出、结余、TOP3 分类,以及差值。两个工具都是只读,Always do。

### 2.4 账单导入助手(`agent-import-assistant`)

**范围**:第一版只收"粘贴文本",不读文件(规避 GBK/zip 解压码问题,用户从手机复制或从解压后的 CSV 全选复制即可)。识别两种格式:微信支付账单、支付宝流水;识别失败时展示"每行:日期,金额,摘要"的兜底格式让用户照此粘贴。

**流程**:解析 → 逐行映射分类(规则表:外卖/美团/饿了么→餐饮,滴滴/加油→交通,内置映射 + 用户历史备注修正) → 输出预览表(日期/金额/摘要/建议分类/重复标记) → 用户逐行勾选(重复行默认不勾) → 确认后按 20 条一批入账,进度提示,失败行单独列出可重试。

**边界**:金额非法或为 0 的行标红不可选;转账/理财赎回等"不是消费"的行默认过滤;导入不触碰账户余额(默认不选账户),需要联动余额让用户在账目页逐笔编辑。

### 2.5 总览洞察卡(`overview-insights`)

纯 Rust 规则,不调模型,刷新总览时重算。规则(命中才显示,最多 3 张):
- **预算消耗超前**:本月已过天数占比 < 已用预算占比,且差 ≥10% → "按这个速度月底预计超支 ¥N";
- **单笔大额**:近 7 天有单笔 ≥ 本月支出均值 5 倍 → 列出该笔;
- **订阅临近**:未来 5 天内有订阅扣费 → 列出名称与金额;
- **目标落后**:目标近三月速率 < 要求速率 → 显示缺口。

每张卡右上角"问助手" → 打开抽屉并预填问题(如"这个月预算为什么会超")。

### 2.6 全局抽屉(`agent-drawer`)

- 唤起:⌘K(Windows/Linux Ctrl+K)、右下角悬浮球、各页"问助手"按钮;
- 宽度 400px,覆盖在内容右侧,不挤占布局;Esc 关闭,关闭保留会话;
- 上下文带入:在报表页打开 → 自动附"用户正在看 X 月报表";账目页选中某笔 → 附"用户选中了 Y 月 Z 日 ¥N 的账目"。上下文以 system 附加段注入,不进用户消息。

## 三、原型排版规划(重排)

```
┌────────────┬──────────────────────────────────┬─────────┐
│ 侧栏       │  顶栏:全局搜索 [⌘F]  [+ 记一笔]  │  助手    │
│ ─ 记账 ─   │ ┌────────────────────────────┐   │  抽屉    │
│  总览      │ │ 净资产卡  资产/负债/本月结余 │   │ (400px) │
│  账目      │ ├────────────────────────────┤   │  对话流  │
│  预算      │ │ 本周洞察卡 × N(问助手)      │   │  含确认  │
│ ─ 规划 ─   │ ├──────────────┬─────────────┤   │  卡片    │
│  目标      │ │ 本月预算进度  │ 目标进度     │   │          │
│  订阅      │ ├──────────────┴─────────────┤   │  输入框  │
│ ─ 分析 ─   │ │ 近 30 天收支趋势图           │   │          │
│  报表      │ └────────────────────────────┘   │          │
│  理财      │                                  │          │
│ ⚪悬浮球    │                                  │          │
└────────────┴──────────────────────────────────┴─────────┘
```

- 侧栏三组用小标题分隔(现有 `group` 字段已支持),顺序即使用频率:记账 > 规划 > 分析;
- 顶栏全局搜索是 add-search-tags 的入口,与助手抽屉并列为一等公民;
- 总览从"报表摘要"变成"今天该关心什么":净资产(我现在有多少)→ 洞察(哪里不对劲)→ 进度(离目标多远)→ 趋势(整体走向)。

## 四、方案对比(为什么这么做)

| 方案 | 说明 | 取舍 |
|------|------|------|
| A. 确认卡片(选定) | 助手出结构化卡片,前端渲染,字段可改 | 成本中;可测、可扩展到改预算/改估值 |
| B. 二次对话确认("回复是") | 纯文本追问 | 成本低;改字段要重新打字,体验差 |
| C. 导入走文件选择器 + Rust 解析 CSV | 功能完整 | 要处理 GBK/zip/编码,首版收益低;粘贴文本覆盖 90% 场景 |

选定 A + 粘贴文本导入。演进路径:后续版本若粘贴导入用得多,再把文件解析补上;确认卡片协议稳定后,把"改预算""改估值"也纳入 Ask-first。

## 五、风险与遗留

| 风险 | 等级 | 应对 |
|------|------|------|
| 本地小模型(qwen3:14b)对"追问缺失字段"遵循度不稳 | 中 | system prompt 给 few-shot;解析失败兜底为"出卡片时留空字段让用户补",不阻塞 |
| 微信/支付宝格式变动导致解析失效 | 中 | 解析规则集中在一个模块 + 每种格式留真实样例单测;失效时展示兜底格式 |
| 复盘保存后与报表页口径不一致 | 低 | 数据同源 `review_summary`,报表页只展示不重算 |
| ⌘K 与系统/浏览器快捷键冲突(Tauri WebView) | 低 | 注册失败时只保留悬浮球入口,不报错打断 |
