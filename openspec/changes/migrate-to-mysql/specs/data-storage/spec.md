## ADDED Requirements

### Requirement: 数据保存在 MySQL
系统 SHALL 把全部业务数据(账户、估值、账目、预算、设置、聊天记录)保存在配置的 MySQL 数据库中,且 MUST NOT 创建或依赖本地数据库文件。

#### Scenario: 正常记账
- **WHEN** 用户记一笔账
- **THEN** 该记录写入 MySQL 的账目表,可用任意 MySQL 客户端查询到

### Requirement: 连接配置与凭据保护
系统 SHALL 从应用数据目录的配置文件(或环境变量)读取数据库连接信息;配置文件 MUST 仅当前用户可读,界面 MUST NOT 显示密码。

#### Scenario: 查看连接信息
- **WHEN** 用户打开"数据"页
- **THEN** 显示形如 `mysql://用户@主机:端口/库名` 的描述,不含密码

### Requirement: 连不上数据库时应用仍可打开
系统 SHALL 在启动时无法连接 MySQL 的情况下仍打开窗口,并对每次操作返回明确的失败原因;数据库恢复可用后 MUST 无需重启应用即可继续使用。

#### Scenario: 启动时 MySQL 未运行
- **WHEN** 用户在 MySQL 未启动时打开应用
- **THEN** 窗口正常显示,界面提示无法连接及检查方法,应用不退出

#### Scenario: 之后启动了 MySQL
- **WHEN** 用户随后启动 MySQL 并再次进行任一操作
- **THEN** 操作成功,无需重启应用

#### Scenario: 缺少配置
- **WHEN** 找不到数据库配置文件
- **THEN** 提示配置文件位置以及初始化脚本的名称

### Requirement: 自动建表
系统 SHALL 在首次成功连接时自动创建所需数据表和默认分类;重复连接 MUST NOT 破坏已有数据。

#### Scenario: 全新数据库
- **WHEN** 连接到一个空库
- **THEN** 所有数据表与默认分类被创建,应用可直接使用

### Requirement: 可重复运行的初始化脚本
系统 SHALL 提供初始化脚本,创建数据库与仅拥有该库(及测试库)权限的专用账号、生成随机密码并写出配置;重复运行 MUST 沿用已有密码且不重置数据。

#### Scenario: 第二次运行
- **WHEN** 配置已存在时再次运行脚本
- **THEN** 沿用原密码,已有数据不变

### Requirement: 多步写入的原子性
系统 SHALL 保证由多条语句组成的写入要么全部生效要么全部不生效。

#### Scenario: 设置预算
- **WHEN** 同月总预算被反复设置
- **THEN** 始终只保留最后一条,不会出现只删不插或重复

#### Scenario: 新建账户
- **WHEN** 新建账户并给出初始金额
- **THEN** 账户与其初始估值同时存在

### Requirement: 迁移旧版本数据
系统 SHALL 提供一次性导入工具,把旧版本的数据迁入 MySQL;工具 MUST 只读打开源文件,MUST 仅在目标库无业务数据时才导入,且导入后各账户余额与旧版一致。

#### Scenario: 导入旧数据
- **WHEN** 对一个旧格式(无录入时间戳)的文件运行导入
- **THEN** 账户、估值、账目、预算、分类、聊天记录全部导入,分类编号与账目关联保持一致,余额不变

#### Scenario: 目标库已有数据
- **WHEN** MySQL 中已存在账户或账目时运行导入
- **THEN** 工具中止并说明原因,不修改任何数据

#### Scenario: 源文件不被修改
- **WHEN** 导入完成
- **THEN** 旧文件内容保持原样
