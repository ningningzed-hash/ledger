## Context

现有 `Agent` trait 同步接收 `&Connection`,并且 `send_chat` 在持有数据库互斥锁期间调用 Agent。接入 LLM 后一次回复可能耗时数十秒,若仍持锁会阻塞所有界面读写;若命令为同步命令,Tauri 会在主线程执行,窗口会卡死。

## Goals / Non-Goals

**Goals:**
- 使用本机 Ollama 的 `qwen3:14b`,零云端依赖。
- 模型能通过工具读写账本,回答基于真实数据。
- 人设与理财理念可由用户调整。

**Non-Goals:**
- 流式输出(首版整段返回,后续再做)。
- 向量检索/长期记忆。
- 具体证券的买卖建议、行情预测。

## Decisions

1. **协议**:调用 Ollama `/api/chat`,`stream:false`,`think:false`。理由:14B 模型开启思考会显著拉长延迟,记账与查询场景不需要;若响应仍含 `<think>` 块则剥离。
2. **工具循环**:最多 6 轮;每轮把 `tool_calls` 的执行结果以 `role:"tool"` 追加。超过上限则返回已有文本或提示。
3. **连接占用**:使用数据库连接池,只在读取设置/历史、执行单个工具时短暂取用连接,调用模型期间不占用。`send_chat` 使用 `async` 命令并通过 `spawn_blocking` 执行阻塞的 HTTP 请求。
4. **HTTP 客户端**:选用 `ureq`(阻塞、体积小),符合"体积小"的目标。
5. **工具集**(无删除类):
   - 读:`get_overview`、`list_accounts`、`list_transactions`、`category_summary`
   - 写:`add_transaction`、`set_monthly_budget`、`update_asset_value`
   金额参数以"元"传入,由程序换算为整数分;分类以名称传入,未匹配时返回可选分类列表让模型重试。
6. **提示词组装**:系统提示 = 人设 + 理财理念 + 行为规则(必须用工具取数、不编造、写操作后复述、缺信息先追问) + 动态上下文(今天日期、本月总览)。人设与理念默认值内置于程序,用户修改后存入 `setting` 表。
7. **对话历史**:取最近 20 条 `chat_message` 作为上下文。
8. **设置存储**:`setting(key, value)` 键值表;读取时缺省回落到内置默认值。

## Risks / Trade-offs

- 14B 模型可能工具参数出错 → 工具内做严格校验,错误以文本返回给模型自行纠正;写操作成功后在回复中复述,便于用户发现错误。
- 模型可能越权给出投资建议 → 理财理念中明确边界并声明"不构成投资建议"。
- 首次推理需加载模型,延迟较高 → 界面显示"思考中",请求超时设为 120 秒。
- 误记账无法由助手撤销 → 用户可在"账目"页手动删除。
