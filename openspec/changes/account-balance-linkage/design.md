## Decisions

1. **余额是推导值,不是存储值。** 余额 = 最新估值金额 + 满足条件的收支净额。好处:删除或补录账目无需额外维护,不会出现余额与流水不一致。
2. **哪些收支计入:** 同时满足 `账目日期 >= 估值日期` 且 `账目录入时间 > 估值录入时间`。
   - 估值之后才录入的账目会计入。
   - 估值之前已录入的账目视为已包含在这次估值里,不重复计入。
   - 日期早于估值日的补记账目不计入(真实余额已包含它)。
3. **用时间戳而不是自增 id 判断先后。** 自增编号并不保证"后录入的更大":删除最大编号后可能被复用(SQLite),备份恢复与旧数据导入也会带入显式编号。时间戳使用进程内严格单调递增的微秒值,避免系统时钟精度造成并列。
4. **旧数据导入:** 旧版没有该列的数据导入时记为 0。旧账目录入时间为 0,不会大于任何估值的录入时间,因此导入后余额不变;之后新记的账目正常计入。
5. **房产不记收支:** 房产没有流水,收支会让估值失真。

## Risks

- 系统时间被大幅回拨时,"先后"判断可能出错;个人单机使用可接受。
- 补记早于估值日的账目不会影响余额,这是有意的;用户需要时应更新估值。
