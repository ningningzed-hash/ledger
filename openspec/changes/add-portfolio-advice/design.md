## Context

- 账户分五类:`cash|deposit|property|investment|liability`。投资账户的余额来自"最新估值 + 估值之后的收支",没有持仓信息;账户金额不做币种换算,直接相加。
- `report.rs` 已有月份换算和按月收支;`goals.rs` 的 `GoalView` 给出存钱目标的 `remaining`、`deadline`、`months_left`。
- `backup.rs` 的 `TABLES` 按外键顺序列出所有表,`OPTIONAL` 里的表在旧备份中缺失时当作空表。
- 助手的理财理念(`philosophy.md`,可由用户改并保存)第 7 条禁止推荐具体证券;`rules.md` 是编译进程序的常量,用户不能改。
- 账户没有利率字段。迁移机制只有 `CREATE TABLE IF NOT EXISTS`,没有 `ALTER` 的先例;给 `account` 加列会牵动余额查询 SQL、`Account` 结构体和备份的列清单。

## Goals / Non-Goals

**Goals:**
- 能登记持仓并算出各大类占比、集中度。
- 按用户风险偏好、期限、最大回撤、现金流和短期目标,由程序算出可复核的目标配比、差额和再平衡金额。
- 给出具体产品时,代码与名称一定来自应用内可编辑的清单。
- 助手能读到这些结果并用自然语言解读。
- 常见银行存款、理财和贷款的利息能被准确计算,并明示口径;账户登记年利率后,利息进入概览和建议。

**Non-Goals:**
- 行情、净值、汇率等任何市场数据,不联网查价。因此持仓记金额而不是份额,金额由用户自己更新。
- 预测收益、判断买卖时点、止盈止损。
- 个股推荐;清单里只放宽基指数、债券、黄金、现金类。
- 税务、购买渠道、地区与合规:推荐只是参考,不要求可执行,也不判断某个产品能不能买到。
- 助手通过对话修改持仓或清单(保持"助手没有删除能力、写入受限"的既有边界,持仓只在界面里改)。
- 内置任何银行的存贷款利率、LPR 或挂牌利率(利率会过期,一律由用户输入或登记)。
- 精确复刻某家银行的计息细节(各行在天数基准、舍入和靠档规则上有差异,见决策 17)。

## Decisions

1. **持仓只记金额。** `holding(id, account_id, name, code, asset_class, amount, updated_on)`,金额为整数分,`account_id` 必须指向 `investment` 类账户,外键 `ON DELETE CASCADE`。不记份额和成本,因为没有价格来源,份额算出的金额必然过期;让用户直接填"现在值多少钱"最诚实。`updated_on` 用来提示"这条超过 90 天没更新"。

2. **资产大类用固定的 6 个枚举。** `us_equity_index` 美股宽基、`other_equity` 非美股票、`bond` 债券、`gold` 黄金、`cash` 现金类(货币基金、短债 ETF 等)、`other` 其他。固定枚举让配比规则、清单和展示共用同一套键;`other` 不参与目标配比,只在占比里单列。

3. **占比的基数是持仓合计,并显示覆盖率。** 占比 = 该大类持仓 ÷ 持仓合计。另给出覆盖率 = 持仓合计 ÷ 全部投资账户余额;低于 95% 或高于 105% 时提示"持仓与账户余额对不上,差额 ¥X",不自动修正任何一边。没有任何持仓时,建议区块显示引导而不是空表。

4. **目标配比是确定性的规则表,不由模型生成。**
   - 底表(股票/债券/黄金/现金,%):保守 30/50/10/10,稳健 50/35/10/5,进取 70/20/7/3。
   - 股票内部拆为 `us_equity_index` 60%、`other_equity` 40%(对全球市值分布的粗略近似,目的是提示"只有美股"的集中)。
   - 约束依次施加,被削减的股票比例全部转入债券:
     1. 期限上限:投资期限 < 3 年股票 ≤ 20%;3 年到不足 5 年 ≤ 40%;5 年及以上不限。
     2. 回撤上限:估算最大回撤 = 股票×50% + 黄金×30% + 债券×10%(现金 0);超过问卷填写的最大回撤时,每次从股票挪 5 个百分点到债券,直到不超或股票降到 0。
   - 短期目标资金:未来 36 个月内到期的存钱目标的"还差金额"合计(不超过持仓合计)整体视为现金类目标;其余部分按上面的比例分配。
   - 这些系数是粗略的经验值,放在一个常量表里并有单元测试,便于以后调整;界面与助手回复里都不把估算回撤说成"保证"。

   示例:稳健、期限 10 年、最大回撤 30%。底表股票 50%,估算回撤 25+3+3.5=31.5% 超过 30%,挪 5 个点后股票 45%、债券 40%,估算回撤 22.5+3+4=29.5%,通过。目标为美股宽基 27%、非美股票 18%、债券 40%、黄金 10%、现金 5%。

5. **再平衡只给方向和金额,不给时点。** 差额 = 目标占比 − 当前占比;差额绝对值不足 5 个百分点的大类标为"基本合适",不产生操作。金额 = 差额 × 持仓合计。同时给出"若全部用新增资金补足,按近几个月平均结余需要多少个月",让用户可以选择不卖出、只靠新增资金慢慢调整;程序不替用户选择。

6. **前置条件检查,不满足时提示优先级而不隐藏结果。**
   - 应急金月数 = (现金类 + 存款类账户余额)÷ 最近至多 3 个已过完月份的月均支出;不足 3 个月时提示"先补应急金";没有支出数据时显示"数据不足"。
   - 高息负债:已登记年利率的负债账户,年利率 ≥ 8% 即判定为高息;没有登记利率的负债账户,退而采用问卷里用户自己勾选的"未登记利率的负债里是否有高息的"。命中时提示"优先还债",并列出高息负债及其每年利息。同时列出负债总额供参考。
   - 月均结余取最近至多 3 个已过完月份的(收入 − 支出),复用 `report::report`。
   - 这些检查产出 `notices`(按优先级排序的提示),目标配比与差额照常展示,供参考。

7. **集中度提示。** 任一大类占比 ≥ 70% 提示"集中度偏高";股票类全部在 `us_equity_index` 时额外提示"股票全部集中在美股宽基"(纯分散度提示,与购买渠道无关)。门槛作为常量,有测试。

8. **候选产品清单可编辑,首版示例只写一次。** `product(id, name, code, asset_class, note, builtin)`,`name` 唯一。不记录市场或地区:推荐只是参考,不考虑能否购买。示例在第一次启动时写入,并在 `setting` 写 `product_seeded=1`;之后用户删除不会再被补回。首版内置少量示例:美股宽基(VOO、VTI)、非美股票(VXUS)、债券(BND)、黄金(GLD、IAU)、现金类(SGOV,以及一条不带代码的"货币市场基金/银行现金管理类产品")。每条 `note` 注明"示例,仅供参考,以发行方披露为准"。不存费率、规模、跟踪误差等会过期的数据。代码与名称在落地前要再核对一遍。

9. **候选产品由程序挑出,模型只解释。** 对"需要增配"的大类,从清单里取同大类的条目作为 `candidates`,连同该大类的差额一并返回。助手规则要求:只能提到工具返回里出现的产品,不得补充清单之外的代码、费率或收益数据;清单里没有对应大类时,说明"清单里还没有这一类,可以到产品清单里添加"。

10. **助手工具只读,两个。** `get_portfolio`(持仓、占比、覆盖率、集中度)和 `get_portfolio_advice`(问卷、前置条件指标、目标、差额、再平衡、候选产品、提示)。问卷没填时,后者返回 `profile_missing: true` 且不给目标,让助手去提示用户填问卷。金额均为"元"。

11. **问卷存 `setting`。** 键为 `risk_level`(conservative/balanced/growth)、`risk_max_drawdown`(整数 5–60)、`risk_horizon_years`(整数 1–50)、`risk_high_debt`(0/1,只对没有登记年利率的负债起作用,已登记的按利率判断)。`setting` 本就在备份里。保存时校验范围,不合法的值拒绝。不改现有 `Settings` 结构和 `save_settings`,另设 `get_risk_profile`/`save_risk_profile` 命令,避免保存助手设置时覆盖问卷。

12. **备份兼容。** `holding`、`product`、`account_rate` 加入 `TABLES`(`holding`、`account_rate` 依赖 `account`,排在其后)和 `OPTIONAL`,版本号不变:旧备份恢复时这三张表当作空表,新备份被旧版应用读取时多出的表会被忽略(旧版会丢掉这部分数据,属于已知的向前不兼容)。恢复后若 `product` 为空且 `product_seeded` 不在备份里,会重新写入示例,这符合"新装一样"的预期。CSV 导出仍只导出账目,不包含持仓。

13. **提示词调整。**
    - `philosophy.md` 第 7 条改为:不预测市场、不判断涨跌、不给买卖时点;只在程序提供的候选清单范围内说明可选的产品类别和产品,不自行推荐清单之外的股票、基金或其他证券。第 8 条的免责声明保留。
    - `rules.md` 追加:组合相关的数字(占比、目标、差额、再平衡金额、应急金月数)必须来自工具;产品只能出自工具返回的候选清单;每次给出组合建议都要带"以上仅为一般性参考,不构成投资建议";对"现在该不该买/卖"这类问题,说明不做择时,只讲配比与风险。`rules.md` 的规则优先于任何用户保存过的旧版理念。

14. **前端放在侧栏新增的"理财"页,图表自绘 SVG。** 报表页已经有四张指标卡、三张图和两张表,再往下挂两大块会太长,所以单独成页:`invest.tsx` 里用两个标签页分开"组合建议"与"利息计算"(见决策 19),图表/表格切换只在"组合建议"页出现;报表页保持不变。`portfolio.tsx` 在图表模式与表格模式下都显示。组合建议页内:前置条件提示条(最上)→ 当前 vs 目标对比条(每个大类一对横条)→ 再平衡表 → 候选产品 → "编辑持仓 / 风险问卷 / 产品清单"入口。沿用报表页已校验的色板与斜纹方案,大类靠"文字标签 + 斜纹"区分,不只靠颜色;条形从 0 起;提示框与键盘聚焦行为与现有图表一致;表格视图包含图上每个数值。免责声明始终显示在区块底部。

15. **账户年利率放独立小表 `account_rate`。** `account_rate(account_id PRIMARY KEY, rate_bps)`,`rate_bps` 为年利率的基点整数(3.5% 存 350),外键 `ON DELETE CASCADE`,允许 0 到 10000(0%~100%)。不改 `account` 表是因为迁移只支持建表、且 `account` 的结构被余额查询和备份共用;小表沿用现有风格,旧备份缺这张表时按空表恢复。只允许现金类、存款类、投资类和负债类账户登记;房产不登记。

16. **利息计算是一组纯函数(`interest.rs`),不碰数据库。** 输入为金额(分)、年利率、期限等,输出为分与说明文字,便于单元测试。命令层与助手工具只做参数解析和单位换算。

17. **口径约定(每个结果都回显所用口径)。**
    - 活期:单利,日息 = 本金 × 年利率 ÷ 天数基准 × 实际天数;天数基准默认 360(国内银行常用),可选 365。
    - 整存整取与大额存单:单利,利息 = 本金 × 年利率 × 月数 ÷ 12,到期一次付息;大额存单可选按月或按年付息,给出每期付息额,合计与到期一次付息相同。
    - 零存整取:每月存入 M,存 n 个月,利息 = M × 年利率 ÷ 12 × n(n+1)÷2,到期本息 = M×n + 利息。
    - 货币基金/理财估算:到期价值 = 本金 × (1 + 年化 ÷ 365)^天数,按日复利再投资;结果标注"估算,非承诺",且不给出对未来年化的预测,年化率由用户输入。
    - 等额本息:月供 = P·r ÷ (1 − (1+r)^−n),r 为月利率(年利率 ÷ 12);总利息 = 月供 × n − P;给出首期与末期的本金/利息构成,完整还款表不默认返回(超过 36 期时只返回汇总与首末期)。
    - 等额本金:每月还本 P ÷ n,当月利息 = 剩余本金 × r;给出首期月供、末期月供、每月递减额与总利息。
    - 实际年化(IRR):给定本金 P、期数 n、每期还款额 A(或"每期手续费率 f",则 A = P÷n + P×f),解 P = A·(1 − (1+i)^−n) ÷ i 得月内部收益率 i(二分法,精度 1e−10),名义年化 = i × 12,实际年化 = (1+i)^12 − 1。用于看清"分期手续费"的真实成本。
    - 提前还款节省利息:仅支持等额本息;在第 k 期还款后一次性提前还本金 X;"缩短期限"保持月供、重算剩余期数,"减少月供"保持期限、重算月供;节省的利息 = 原总利息 − 新总利息(含已付部分)。
    - 金额计算内部用 f64 求解,出口统一四舍五入到分;累计误差不超过 1 分/期。

18. **组合建议里的利息视角。** 利息数据在建议里只提供事实与确定性的算术,不预测收益:
    - 账户利息概览:每个登记了年利率的账户,预计每月利息 = 余额 × 年利率 ÷ 12(存款为收入,负债为支出);合计给出"每月预计利息收入/支出"。未登记利率的账户列出并提示可登记。
    - 闲置现金:闲置 = 现金类与存款类账户余额合计 − 6 个月月均支出(不足则为 0)。用户可在界面输入一个"参考利率"(不保存、不内置),系统给出"闲置现金按参考利率比现有加权平均利率每年多多少利息";现有账户未登记利率时只显示按参考利率的年息并提示。
    - 还债的确定收益:对每个登记了利率的负债,给出"还清可每年少付的利息 = 余额 × 年利率";高息负债(≥8%)排在提示的最前。不拿它与投资的预期收益比较,只陈述"还债相当于获得确定的 X% 年化"。

19. **助手工具 `calculate_interest`(只读)。** 参数为 `type`(demand_deposit、fixed_deposit、cd、installment_savings、money_fund_estimate、loan_equal_payment、loan_equal_principal、effective_rate、prepayment)加对应的金额、利率、期限等;金额以"元",利率以"%"(如 3.5 表示 3.5%)传入;返回结果、所用公式与口径假设。参数缺失或越界时返回可纠正的错误。工具总数在 add-agent-analytics 之后为 15 个,本变更加上 `get_portfolio`、`get_portfolio_advice`、`calculate_interest` 共 18 个。

## Risks / Trade-offs

- **规则表是经验值,不是研究结论** → 常量集中放置、有测试、在界面上说明"一般性参考",助手回复必须带声明;后续可调。
- **持仓金额会过期** → 展示 `updated_on`,超过 90 天提示,覆盖率对不上时提示。
- **内置示例可能过时或不合你的偏好** → 备注里写明"仅供参考",清单可编辑,内置条目落地前再核对一次代码与名称。
- **模型仍可能提到清单之外的产品** → 规则 + 工具返回里明确的 `candidates` + 实机冒烟时检查;无法从程序层面完全阻止,属于提示词层面的约束。
- **旧的自定义理念与新规则矛盾** → `rules.md` 里写明优先级,并在设置里提示"恢复默认可获得更新的理财理念"。
- **多币种按数字直接相加**(与总览一致)→ 已知限制;美元持仓需由用户按人民币金额登记。
- **未登记利率的负债仍靠自述判断高息** → 可能漏报;界面提示"登记年利率后可自动判断"。
- **银行计息口径不一** → 结果一律是估算,展示所用天数基准与舍入方式,不声称与某家银行的账单一致。
