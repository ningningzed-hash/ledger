## Decisions

1. **备份是 JSON 文件。** 内容为所有数据表的行,带 `format` 与 `version` 字段。不依赖 `mysqldump` 等外部工具,也与数据库引擎无关。
2. **导出用一致性快照。** 在一个 `WITH CONSISTENT SNAPSHOT` 事务里读取所有表,不会读到写了一半的数据;数字列用预编译协议读取,保证金额是数字而不是字符串。先写临时文件再改名,避免留下写了一半的备份。
3. **恢复是单个事务。** 先在不碰数据库的前提下完整解析并校验文件(格式、版本、全部数据表、字段类型);校验通过后保存安全备份,再在一个事务里"按外键逆序清空、按外键顺序写入"。任何一步出错(例如外键冲突)都不会 commit,现有数据原样保留。
4. **后加入的表可缺失。** 目标、订阅相关的表是后来才有的,旧备份里没有:缺失当作空表;其余数据表缺失仍判为无效备份。订阅的"入账记录"随备份一起带走,所以恢复后再入账不会重复。
5. **只接受已知列。** 恢复时只读取白名单列,文件里的多余字段被忽略,不会被拼进 SQL。
6. **CSV 防公式注入。** 以 `= + - @` 开头的文本单元格前加 `'`;开头加 BOM 让 Excel 正确显示中文。
7. **自动备份仅在启动时执行。** 实现简单;长期不重启的使用方式下按天备份会不够及时,后续可改为定时。

## Risks

- 备份文件未加密,放在云盘或共享位置时需用户自行保管。
- 旧的 SQLite 备份(`.db`)不能直接恢复,需先用 `migrate-to-mysql` 中的导入工具迁入。
