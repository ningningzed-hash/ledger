## Decisions

1. **进度是推导值,不单独记录。** 目标只保存名称、类型、目标金额、截止日期和关联的账户;当前金额每次由账户余额算出。记账、更新估值、删除账目都会自动反映到目标上。
2. **存钱不能关联房产与负债,还债只能关联负债。** 房产的估值靠手动更新、也不能随时取用,不适合作为"攒钱"的对象;负债的"余额"是欠款,方向相反。后端和界面两边都按这个规则过滤。
3. **还债的进度要有起点。** 建立目标(或更换关联账户)时记录当时的欠款作为起点,进度 = (起点 − 当前欠款) ÷ (起点 − 还清线)。欠款反而增加时进度为 0,不为负。只改名称、金额、日期不会重置起点。
4. **速度按"回看起点月月底到现在"估算。** 最多回看 3 个月;实际跨度是这几个整月再加上本月已过去的部分,否则刚过月初时会把速度高估近一倍。关联账户最早的估值就在本月,则没有历史可比,速度为"未知",不给状态判断而不是瞎猜。
5. **状态由期限与速度共同决定。**
   - 已达成:超额也算,进度封顶 100%。
   - 已逾期:有截止日、已过、尚未达成。
   - 进度正常 / 稍落后:速度不低于 / 低于"每月需要的金额"。速度为 0 或为负也算稍落后。
   - 暂无法判断:有截止日但速度未知。
   - 没有截止日:只显示进度,不判断快慢。
6. **预计达成月份只在速度为正时给出。** 速度为 0 或为负时明确说"按目前的趋势暂时无法达成";超过 100 年的预测不给出。
7. **已逾期的目标仍可编辑。** 只有"修改了截止日期"才要求新日期不早于今天,这样可以只改名字、金额或关联账户。
8. **日期由前端按用户本地日期传入。** 后端不读系统时间,既便于测试,也避免时区在跨天时造成歧义。
9. **备份兼容旧文件。** 目标是后来加入的表,旧备份里没有:缺失当作空表,不判为无效备份。恢复仍是整体替换,所以旧备份恢复后目标会被清空。
10. **助手只读。** `list_goals` 返回进度、所需金额、实际速度与状态,并在说明里区分"每月需要"与"近期实际",避免模型把两者说混。不提供创建或删除目标的工具,与助手"不做破坏性操作"的原则一致。

## Risks / Trade-offs

- 速度只是近几个月的平均值,工资发放不均、一次性大额支出都会让它偏离,界面上措辞用"近几个月平均"和"按这个速度预计"。
- 已归档账户不再计入目标的合计(与总览一致);如果目标的所有账户都归档了,金额为 0。
- 关联账户的币种不同时直接相加(与总览一致,是已知限制)。
